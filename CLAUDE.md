# GamblingGnomes — Project Conventions

## Tech stack (mirrors ProjectGamble)

- **Unity** with **URP** (`com.unity.render-pipelines.universal`).
- **Netcode for GameObjects** (`com.unity.netcode.gameobjects`) for multiplayer — server-authoritative model.
- **New Input System** (`com.unity.inputsystem`).
- **DOTween** (`Assets/Plugins/Demigiant`) for tweening.
- **Odin Inspector** (`Assets/Plugins/Sirenix`) for inspector tooling — used selectively, not everywhere.
- **Facepunch.Steamworks** (`Assets/Plugins/Facepunch.Steamworks`) for Steam integration.
- **Addressables**, **Timeline**, **Visual Effect Graph**, **Post-processing** as needed.
- C# language version: 9.0.

All of the above packages/plugins have already been installed/copied into this project to match ProjectGamble (`Packages/manifest.json` + `Assets/Plugins/`).

## Folder structure

Follow ProjectGamble's layout:

```
Assets/
  Scripts/
    Game.Runtime/   — all gameplay code (asmdef: Game.Runtime)
    Game.Editor/    — editor-only tooling (asmdef: Game.Editor, includePlatforms: Editor)
  Prefabs/
    UI/             — UI prefabs, with Buttons/ and feature subfolders colocating anim + controller assets
  Scenes/            — Bootstrap.unity (or equivalent) + Gameplay.unity pattern: bootstrap scene loads gameplay
  Fonts/             — one folder per font family
  Textures/
  Materials/
  Configs/           — ScriptableObject data assets
  Resources/         — kept minimal (only assets that must be Resources.Load'ed, e.g. DOTweenSettings)
  Plugins/           — third-party libs dropped in as source/DLL (Demigiant, Sirenix, Facepunch.Steamworks)
  Settings/          — URP assets, Input Actions, volume profiles, Build Profiles
```

Do not scatter scripts outside `Assets/Scripts/`. Do not create per-feature asmdefs — keep the flat two-assembly split (`Game.Runtime` + `Game.Editor`) unless the project grows enough to justify splitting.

## C# code conventions

**Namespaces**: mirror the folder path exactly, rooted at `Game.Runtime` / `Game.Editor` (e.g. a script in `Scripts/Game.Runtime/UI/Poker/` → `namespace Game.Runtime.UI.Poker`).

**Naming**:
- PascalCase for all types; file name matches class name.
- UI `MonoBehaviour`s prefixed `UI` in code (`UIButton`, `UIManager`) — no underscore in the C# identifier.
- Feature/domain prefix for grouping instead of relying only on namespaces (e.g. all poker-specific classes start with `Poker*`).
- Suffixes carry meaning: `*Manager` (singleton-style coordinators), `*Controller` (behavior/logic owner), `*Data` (NetworkBehaviour holding `NetworkVariable`/`NetworkList` state — the "model"), `*Stage` (state-machine step), `*Visual` (presentation-only component), `*Database` (ScriptableObject lookup table), `*Constant`, `*Settings`.
- Interfaces prefixed `I` (`IGameMode`).

**Base types**:
- `NetworkBehaviour` for anything with server-authoritative state.
- Plain `MonoBehaviour` for local/visual-only components.
- `ScriptableObject` (with `[CreateAssetMenu]`) for static config/data assets.
- Structs implementing `INetworkSerializable, IEquatable<T>` for small networked value types (like `CardData`).
- Abstract base classes for pluggable step systems (a `*Stage` base with `StartStage`/`EndStage`, subclassed per concrete stage; a hallucination effect base with `Begin`/`Stop` hooks).

**Fields & properties**:
- `[SerializeField] private Type _fieldName;` — underscore-prefixed camelCase for private serialized fields.
- `[field: SerializeField] public Type Foo { get; private set; }` for "inspector-set, code-read-only" public members.
- `[HideInInspector] public NetworkVariable<T> Foo = new(...);` — public field (not property) for NGO NetworkVariables, hidden from inspector.
- `[Header("Section Name")]` to group inspector fields logically (e.g. "Player Info", "Game State", "References").
- Constants in PascalCase, not SCREAMING_CASE (`private const int MinimumPlayersToStart = 2;`).
- No regions. No XML doc comments. Comments are rare — only for non-obvious business logic, one line max.

**Patterns**:
- Singleton managers: hand-rolled `public static X Instance { get; private set; }`, set in `Awake()` with a duplicate-destroy guard. No generic `Singleton<T>` base.
- Data/logic split: put networked state in a dedicated `*Data` `NetworkBehaviour` (model), expose it via a `Data` property from the owning controller/stage (logic), keep UI as a separate view that reads `Data` and subscribes to its change events.
- State machines: a list of stage objects + current index, `NextStage()` calling `EndStage()`/`StartStage()` on transition.
- Event-driven sync: plain `event Action`/`event Action<T>`, subscribed in `OnNetworkSpawn`/`OnEnable`, unsubscribed symmetrically in `OnNetworkDespawn`/`OnDisable`. Prefer `NetworkVariable<T>.OnValueChanged` / `NetworkList<T>.OnListChanged` for state→view sync over manual RPC broadcasts of state.
- RPCs: use the modern NGO attribute style `[Rpc(SendTo.Server, ...)]` / `[Rpc(SendTo.Owner, ...)]`, not legacy `[ServerRpc]`/`[ClientRpc]`. Method names keep the `RPC` suffix (`ActivateRPC`, `ReadyRPC`).
- Async: use Unity's native `Awaitable`/`Awaitable<T>`, not UniTask or coroutines, for new async code. Every async operation takes `CancellationToken ct = default` and undoes its own setup on cancel; a temporary handler subscribed inside an awaitable wrapper is unsubscribed on *every* path, cancel included. `async void` is banned except for a Unity/UI event handler, and that handler catches. **A re-entry guard flag is released in `finally`, never on the success path alone** — one throw and the button is dead for the rest of the session (`UIFindLobby`, `UIPauseMenu`, `GameNetworkManager._joiningLobby`). UI handlers pass `destroyCancellationToken`, so an await outliving its object unwinds instead of writing into a corpse.
- Tweens: cache `Tween` references in a field, `.Kill()` before restarting.
- No DI container / service locator. Wire dependencies via `[SerializeField]` inspector refs or static `Instance` singletons.
- **Never resolve a dependency with `FindFirstObjectByType`/`FindAnyObjectByType`/`Camera.main`** (editor tooling excepted) — a dependency arrives serialized, is handed over by its owner's lifecycle (`Initialize(owner)`), or comes from a registry that sets itself up and tears itself down in its own lifecycle (`GameCamera`, `PokerSeat`). A *spawned* prefab is the case that needs the registry: it cannot serialize a reference to the scene it lands in.
- No polling. `Update`/`LateUpdate` is for genuinely continuous work (look smoothing, camera follow) — never for detecting that something changed, and never for `GetComponent`, `Instantiate`, `Find*` or allocation. Cache lookups in `Awake`/`Initialize`.
- Odin Inspector (`[ValueDropdown]`, `[FoldoutGroup]`, etc.) only where plain `[SerializeField]`/`[Header]` can't express the need (dynamic dropdowns, foldout grouping) — not as the default on every class.

## Design principles

Hold code to an industry-standard design bar rather than inventing bespoke structure. When facing a design choice, reach for the solution many teams already converge on; check whether this codebase (or the wider industry) already has the shape for it before writing a new mechanism.

- **SOLID + KISS + DRY.** Split into clear modules that can be reused and assembled, not monoliths.
- **Minimise coupling.** A component that needs a dependency takes it from an event or an injected reference rather than reaching into a concrete singleton — a module that can only work in the one place it grew up in is not reusable.
- **Domain-agnostic mechanism, concrete domain code.** Genericity is a property of the module boundary, not of every line. A reusable mechanism carries no poker/Steam/lobby word in its name or API (`PlayerBoneScaleController`, `PlayerActionAnimator`, `PlayerSpawnPoint` — the mechanism is the same whatever sits in it). Code built on top of it stays explicit: `DealCardToPlayer`, `SwapPotToLosers`, `OnPotItemsChanged` — never `Assign`, `Process`, `OnValueChanged`. **A name must state its purpose on sight; that outranks genericity.** A vague name in domain code is a defect, not an abstraction.
- **Don't over-generalize.** Structural abstraction (interface, type parameter, base hierarchy) costs something: two real uses justify it, one does not. Write the concrete case, and pull the mechanism out when the second caller actually arrives. Duplication twice is a signal, three times is a refactor.
- **Data, logic and visual are three responsibilities, never mixed in one class.** Data owns state (`NetworkVariable`, serialized config) and no behaviour; logic owns rules and transitions and touches no `Renderer`/`Animator`/`Image`/tween; visual renders and animates and never decides a rule or writes authoritative state. Visual *reacts* to data through events and `OnValueChanged` — it never drives. `PokerGameData`/`PokerGameMode`/`PokerVisual` and `PlayerData`/`PlayerController`/`PlayerVisual` are the reference shapes.
- **Downward references only.** `GameModeController` → `PokerGameMode` → `PokerModule`/`PokerStage`; a child never calls up, it raises an `event` the parent listens to. Cross-module talk goes through events or a small shared contract, not a reach into the other module's concrete type.
- **Template method for extension points.** A base class keeps its own step non-virtual and calls a `protected virtual` hook from inside it, so a subclass extends behaviour without the parent ever being edited, and shared work can't be skipped by a subclass that forgets `base.Foo()`:

  ```csharp
  private void Tick(float deltaTime)
  {
      // shared work the base always does
      OnTick(deltaTime);
  }

  protected virtual void OnTick(float deltaTime) { }
  ```

  The outer method carries the invariants (guards, ordering, state flags); the `OnX` hook carries only the subclass's own work. Applies to every extension point, not just tick — `Start`/`End`, `Bind`/`Unbind`, `Enable`/`Disable`. See `PokerStage` (`StartStage`/`OnStartStage`), `UIPokerView` and `PokerVisual` (`OnBind`/`OnUnbind`).
- **Every system has an explicit lifecycle.** Bind and unbind through paired hooks — `OnEnable`/`OnDisable`, `OnNetworkSpawn`/`OnNetworkDespawn`, `OnBind`/`OnUnbind`, or a static `OnInstanceChanged`-style event. Never poll for a dependency in `Update()` and rebind when you notice it changed: that hides the binding in the per-frame path and leaves no single point where the subscription is released, so handlers leak. Unsubscribe in the reverse order of subscribing, and null a reference only after the unsubscribe that needs it.
- **Animate with DOTween, not hand-rolled interpolation.** A per-frame `Vector3.Lerp`/`Quaternion.Slerp` toward a moving target bakes the curve into decay maths and offers no hook for "then do this". A tween makes easing, duration, delay, loops, callbacks and sequences tunable after the fact. Expose duration and `Ease` as `[SerializeField]` so they can be retuned without touching code, and prefer `SetEase` over hand-tuned constants.

## Scenes and lifetimes

Two lifetimes: `Bootstrap.unity` is persistent, `Gameplay_*.unity` is loaded additively and disposable.

- Bootstrap owns the services that outlive a match — `NetworkManager`, `GameNetworkManager`, `SteamController`, `GameCamera` + the Cinemachine brain, `UIManager`'s canvas. Gameplay owns the mode, the table, the seats and the players.
- **Bootstrap code must not reference gameplay types.** Gameplay consumes bootstrap services through their registered instance or an interface, never the other way round.
- Gameplay must survive being unloaded and reloaded without leaking a handler or a static: every `+=` in a spawn/enable hook has its `-=` in the mirrored despawn/disable hook, and every static holding state resets under `[RuntimeInitializeOnLoadMethod]`.
- Never assume gameplay is loaded from bootstrap code; go through the async load path. Scene operations in a networked session go through `NetworkManager.SceneManager`.
- **A mode is a prefab the server spawns from the lobby's pick; the gameplay scene holds no mode.** Several modes share `Gameplay_Poker`, so `GameModeController` spawns `GameModeDatabase` entry's `ModePrefab` (a variant of `GameMode_Poker`: its own `_sequence`, `_rules`, `_itemDatabase`, `_hudPrefab`) from `OnInSceneObjectsSpawned`, never `OnNetworkSpawn`, since the mode lays the table from the seats registered when it spawns. A scene `NetworkBehaviour` needs a `NetworkObject` on itself or a parent: `PlayerManager` rode the old in-scene mode's and silently stopped spawning players when moved off it (now under `GameModeController`).
- Exactly one **base** `Camera` + `CinemachineBrain` exists, and it lives in bootstrap. Everything else — the player prefab's first-person rigs, any cutscene rig — is a `CinemachineCamera` the brain blends to. Never hand-drive `Camera.transform`. The one other `Camera` is `Bootstrap/UICamera`, an URP **Overlay** camera in the base camera's stack; it draws the UI and nothing else, and has no brain.

## Netcode rules

- Server is authoritative for spawn/despawn and for every rule. Owner-write `NetworkVariable`s are for input-shaped state only (look angles, identity).
- **Set `readPerm`/`writePerm` explicitly on every `NetworkVariable`** — never rely on the defaults. See `PlayerManager`.
- **A replicated value has one seeder.** When a central system takes ownership of a value, delete any local `OnNetworkSpawn` seed in the same change — components later in the prefab run later, so a stale seed silently stomps the central one.
- **Saving a prefab that carries a `NetworkObject` auto-appends it to `DefaultNetworkPrefabs`, even when an entry already names it.** After a save that creates or re-roots a networked prefab, re-point dead entries, deduplicate by object, and grep the `.asset`.
- Guard server-only work with `IsServer` and owner-only work with `IsOwner` at method entry, not halfway down.
- Don't write a `NetworkVariable` every frame; throttle by a meaningful delta.
- **Subscribe to another object's singleton from `Start`, never `OnEnable`.** Objects in one scene wake in no guaranteed order; an `OnEnable` that finds `Instance` null subscribes to nothing and stays deaf for the session, on whichever machine loses the race. Pair `Start` with `OnDestroy` (`UIMainMenu`, `UIPauseMenu`, `UINetworkLoadingBinder`).
- **A third-party SDK's callbacks are a singleton too.** Hooking Steam callbacks before `SteamClient.Init` loses them silently (the lobby opens, the game never starts). `GameNetworkManager` binds from `Start` **and** `SteamController.OnInitialized` behind a flag, and `StartHost` reports through `OnConnectFailed` when nothing is bound.
- **Hide a loading screen on `OnLoadComplete` for the local client, not `OnLoadEventCompleted`** — the latter never fires for a client joining through synchronization; `OnSynchronizeComplete` is the backstop. See `UINetworkLoadingBinder`.
- **Handle late join by reading the current value in `OnNetworkSpawn` and snapping to it** — a client that only subscribes to `OnValueChanged` shows nothing until the next change, which for a value set before it joined is never.
- Teardown belongs in `OnNetworkDespawn`, not `OnDestroy`.

## UI structure

- **`UIManager` is the one canvas, Screen Space - Camera drawn by `UICamera`, and everything it shows is on the `UI` layer.** `UICamera` is an Overlay camera at `(0, 5000, 0)` culling only `UI`, clearing depth, post/shadows/AA off, using `UI_Renderer` (index 1, no renderer features) so SSAO and the hallucination wave never touch the HUD. A UI object on another layer draws nowhere, silently. Features never ship a canvas; they `Show` into a `UILayer` (`Hud`/`Screen`/`Overlay`). `UI_Manager.prefab`
- **A world-space canvas over a head is on the `WorldUI` layer and draws on top of the world.** A world canvas is depth-tested like any transparent, so the head, the hat or another player clips it, and `sortingOrder` cannot fix that — it only orders transparents among themselves. `PC_Renderer`/`Mobile_Renderer` leave `WorldUI` out of their opaque and transparent layer masks and draw it in the `WorldUIOnTop` Render Objects feature (after transparents, ZTest Always, no depth write). Culling follows the **canvas root's** layer, so children spawned at runtime from `UI`-layer prefabs are covered. `Player_Poker/…/Tag`
- **The `CanvasScaler` lives on the `UIManager` canvas only**, since one on a child canvas silently rescales everything under it. Scale With Screen Size, 1920×1080, Match 0.5.
- **Full-screen panels anchor `(0,0)`–`(1,1)` with zero offsets; corner HUD anchors to its corner.**
- **A stretched frame carries a 9-slice border on its sprite (Single mode, `Image` Sliced); art with a shaped end stays Simple.** Slicing a shaped end pinches it (`button_ability_default`). A progress bar slices its track and leaves the fill Filled.
- **A fan of cards turns about one shared pivot below them, never about each card's middle.** Turning in place opens gaps at the bottom that no angle fixes. The spread comes from the angle alone, no sideways spacing. `PokerCardFanVisual` (`_pivotDrop`, `_fanAngle`), `UIFanLayoutGroup`
- **A tween only moves what no layout group places** (a scale, a fan's openness, or a `Body` stretched inside a layout-owned entry). `UIPokerRankingEntryVisual`, `UI_PokerRankingRow`
- **A list that replicates one entry at a time reaches the view one change at a time, so schedule a staggered reveal by index, not off the first change.** Otherwise later entries snap in unseen. `UIPokerRankingPanel` records when it went up and gives each row the slot `start + rowsAt + index × _rowStagger` whenever it arrives.
- **Hide a HUD section by fading its `CanvasGroup` (raycasts off), not deactivating it, when it must keep listening.** A switched-off view unbinds. `UIPokerHudStateController` fades `UI_Poker/Playing` while the showdown list is non-empty, reading the same list as the board.
- **Pad a layout off the art, not the rect.** A 9-slice keeps decorative overhang at its authored size (`table_ranking`), so padding to the `Image` rect puts content on transparency.
- **A runtime-only HUD prefab is not done until it has been rendered.** Instantiate under a `ScreenSpaceCamera` canvas with the project scaler in a throwaway scene, fill it, `ForceRebuildLayoutImmediate`, render to a `RenderTexture`, write a PNG; this catches ellipsised and overflowing text the hierarchy hides.
- **UI prefabs live in `Prefabs/UI/Components/`, `Screens/` and `Panels/`; screens and `UI_Poker` compose them as nested instances.** A restyle is then one edit. A screen root is full-screen with its own `CanvasGroup`, even when nested in `UI_Manager`. A panel owns everything it references (`Button_Help` under `HandHelper`).
- **A list item is a component prefab referenced as `_*Prefab`, never an inactive template child** (`TMP_Dropdown`'s `Template` excepted). `UI_HallucinationRung`, `UI_PokerBetKind`. For editor preview of a runtime list see `UIPokerHandRankingList` (Build/Clear Preview, `_rebuildAtRuntime`, rows adopted in `Awake`).
- **The second time a widget is drawn, it becomes one component prefab plus one driving component.** Loose copies drift apart silently. `UITimerBar` + `UI_TimerBar.prefab`
- **When swapping a loose object for a prefab instance, collect the old objects before instantiating, and re-point references by search.** A later `Find` returns the replacement; walk every `SerializedObject` for `objectReferenceValue` equal to the old object.
- **A list of choices marks selection once, from the group, and uGUI owns focus.** `UISelectionGroup` owns the pointer; `UISelectionItem` supplies `PointerAnchor`, raises `OnPointed` from `ISelectHandler`, and hover calls `EventSystem.SetSelectedGameObject`. A hand-rolled navigation loop fights the EventSystem. Consumers subscribe to `OnSelectionChanged` only. Item look uses `UIButtonState.Selected`, which outranks `Hovered`.
- **A group that hides clears its selection and remembers it separately.** Otherwise the same entry returning reads as "no change" and is never re-marked. Stash in `_lastSelected`, re-offer on enable behind `_restoreSelectionOnEnable` after re-checking it is active and interactable. `UISelectionGroup`
- **Anything reading a laid-out rect runs in `Rebuild(CanvasUpdate.PostLayout)` via `ICanvasElement`, never in `OnEnable` or a frame later.** A parent's `OnEnable` runs before its children are active and rects read zero, so it passes on scene load and fails on re-show. Register with `CanvasUpdateRegistry.RegisterCanvasElementForLayoutRebuild`, unregister in `OnDisable`/`OnDestroy`, re-request from `OnRectTransformDimensionsChange`. `UISelectionGroup`
- **Layout groups: every child needs a size source.** A plain container inside a layout group carries a `LayoutElement`, or its children collapse onto one spot. A nested layout group reports its own size: turn the parent's `childControlWidth/Height` on and never add a `ContentSizeFitter` to the child, or both write nothing and stack at `(0,0)` (`UI_IconCounter`). A `ContentSizeFitter` on the same object as the layout it sizes lays out at the old height first, so pin heights with `LayoutElement` instead (`UIPokerRankingPanel`).
- **A row or column of widgets is an auto-layout group with a `LayoutElement` per child, never hand-placed anchors**, so hidden buttons and longer text reflow. Only fixed furniture stays anchored.
- **A screen with several sections is one component per section.** `UIPokerView` subclasses bind via `OnBind`/`OnUnbind`; a new section is a new view plus a list entry.
- **`UIButton` resolves state; `UIButtonVisual` subclasses draw it.** `UIButton` holds no `Image`, colour or tween and raises `OnStateChanged(previous, current)`; a new look is a new subclass (`UIButtonSpriteVisual`, `UIButtonScaleVisual`, `UIButtonOffsetVisual`, `UIButtonCanvasGroupVisual` — alpha only). The base finds the button with `GetComponentInParent`, owns the subscription and snaps to the current state on enable.
- **A `UIButtonVisual` subclass never declares `Reset` or `OnDisable`** — it hides the base's and the button reference is never filled or the handler never released. Use `OnReset`/`OnDisabled`.
- **A 3D model on the UI goes through `UIModelView`: `Root` (what visuals turn) → `Tilt` (the lean) → model centred on `Tilt`, scaled into `_bounds`.** Visuals target `Root`, never the replaceable model. Fit from `sharedMesh.bounds` through the local TRS chain, counting only drawn renderers: at 5000 units up the model is inside float32 precision, so `Renderer.bounds` and world round trips give a wrong fit. `UIButtonSpinVisual`, `UIButtonOutlineVisual`
- **A model shown on the HUD is the world prefab itself, with its UI paint authored on the prop.** A UI copy is something no hallucination or art change reaches. `UIPokerBetKindButton` registers on `PokerItemCapRegistry`; `PropUIMaterials` lists unlit `*_UI.mat` per renderer, and `UIModelView` calls `SetIsUI(true)` before anything claims a renderer so `PropMaterialOverrideController` captures it as the authored array.
- **No light is added for UI models**: a directional light on the `UI` mask becomes the world's main light in `Gameplay_Poker`, which has no `RenderSettings.sun`.
- **A button returns itself to rest after a click, and a redraw is not a transition.** uGUI sends the release to whoever took the press, so a button whose click opened a screen stays `Pressed`. `UIButton.ResetState()` clears held flags and forces a refresh; call it from anything that steals the pointer mid-press. `UIButtonVisual` snaps when `previous == current`.
- **A click waits out its press animation before the handler runs.** `UIButton._clickDelay` (0.1 s) is unscaled (`AwaitableUtility.WaitUnscaledAsync`), releases its guard in `finally`, re-checks `this`/`isActiveAndEnabled`/`IsInteractable` after, and 0 means no wait.
- **A hotkey presses the `UIButton`, not the uGUI `Button`, and holds it while the key is held.** `UIButtonHotkey` calls `Submit()` and sets `IsPressedByKey` from `started`/`canceled`; firing only the click never shows `Pressed`.
- **A visual that moves a button moves a `Content` child from a rest pose captured in `Awake`, never the raycast root.** Moving the hit rect makes the pointer exit and re-enter and the press oscillates; reading the live position walks the button away. `Button_ActionPad`
- **A tint a visual paints at runtime is also authored on the `Image`**, or the prefab reads white in edit mode and renders. `Button_Plate`
- **A button styled by a visual sets the uGUI `Button` Transition to None**, or two writers fight over the `Image`.
- **A non-rectangular button narrows its hit area with `UIAlphaHitArea`** (threshold 0.1). It needs Read/Write on the texture and checks `isReadable` first, since writing the property without it throws.
- **A UI overlay blends with what was drawn before it through the blend state (`UI/Blend`), never by reading the backdrop.** `UICamera` has no grab pass. Separable modes only (Normal, Multiply, Screen, Additive, Subtract, Darken, Lighten), picked by `UIBlendShaderGUI`; a stroke is the last sibling of `Content` with `raycastTarget` off. `UI/Blend` writes alpha separately (`Add`, `One OneMinusSrcAlpha`) because `Min`/`Max` would erase alpha in a `RenderTexture`, and fades by lerping toward `_BlendNeutral` because factor modes ignore alpha.
- **When an overlay has exactly one image behind it, sample both in one shader (`UI/Blend Overlay`).** It sits on the base image (sprite stays `_MainTex`) with the stroke as `_OverlayTex`, enabling Overlay/Soft Light/Dodge/Burn and masking by the base's alpha instead of spilling past its silhouette.
- **A custom uGUI shader keeps the stencil block and `UNITY_UI_CLIP_RECT`** (copied from `UI-Default`), or it ignores `Mask`/`RectMask2D`.
- **Build shaders in Shader Graph; full-screen effects are Fullscreen Shader Graphs on a `Full Screen Pass Renderer Feature`.** HLSL only where a graph cannot go (custom blend or stencil state).
- **A full-screen effect's renderer feature is off until somebody sees it.** `PokerHallucinationFullscreenEffect` enables it, clones the material, and fades one float from zero. Adding a feature from script needs `AddObjectToAsset` plus both `m_RendererFeatures` and `m_RendererFeatureMap`, or the next import drops it.
- **A screen-space distortion tapers to zero at the frame edge**, or it samples off-screen and draws a black band. `Hallucination_Wave` multiplies by `sin(PI * x)`, insets with `lerp(uv, 0.5, _EdgeInset)`, and keeps a `Clamp` only as a net.
- **A hand-written `.shadergraph` has no blank line inside an object, and is verified by resolving every edge.** A blank line splits the JSON stream (unnamed parse error); an edge to a missing slot id is dropped silently. Check `ShaderUtil.ShaderHasError`, then each edge. Slot ids: Multiply `A=0 B=1 Out=2`, Sine `In=0 Out=1`, Split `In=0 R=1 G=2 B=3 A=4`, Vector2 `Out=0 X=1 Y=2`, URP Sample Buffer `UV=0 Output=2`. A mesh target (Unlit/Lit) also needs the three vertex blocks (`VertexDescription.Position`/`Normal`/`Tangent`) even with nothing wired to them: URP still emits a `MotionVectors` pass that calls `BuildVertexDescriptionInputs`, and it fails only when that pass compiles, typically in a build. Verify with `pass.CompileVariant` on every pass, since `ShaderHasError` passes it. `Card_Face`, `Card_Wave`, `Card_Rainbow`

- **A card is one `MeshRenderer` box, never a `SpriteRenderer` or two quads.** A `SpriteRenderer` stores a second material and silently renders only slot 0, so every added pass would be invisible; two faces back to back are two transparent objects to sort and z-fight at the seam. Size, face offsets and hit box are authored in the prefab, not derived at runtime. `Card_Poker`, `PokerCardVisual`
- **Card pictures come from one sprite atlas through one shared material; which picture a card shows travels in its mesh, never in a `MaterialPropertyBlock`.** A block takes the renderer out of the SRP Batcher. `Cards.spriteatlasv2` packs the 53 faces (Sprite Packer Mode **Sprite Atlas V2**, or nothing is packed anywhere; rotation and tight packing **off**, or `Sprite.textureRect` no longer describes the picture). `PokerCardMeshCache` copies the card's box once per (front, back) pair with UV2 = the atlas rect of whichever picture each face shows (−Z front, everything else back), and binds the atlas page as the global `_CardAtlas`. The card graphs sample `_CardAtlas` (a global, unexposed property — an exposed one would be shadowed by the material's own default) at `uv0 * uv2.zw + uv2.xy`. A material cannot reference the packed atlas texture, which is why it is a global rather than a material slot. Leave no stale texture slots on card materials: they pull the unpacked PNGs into the build.
- **A card group's depth step must exceed the card's thickness (0.002) and point toward the viewer.** A shorter step makes neighbours interpenetrate. A card's face reads down its own −Z, so nearer the viewer is negative along the anchor's forward: in a fan each later card steps negative so it overlaps the one on its left and every rank corner stays visible. The sign follows which way the group's anchor points, not which arrangement it is. `PokerCardGroupVisual._depthStep`, `PokerCardFanVisual`, `PokerCardRowVisual`
- **Transparent cards are ordered by the depth step, not the depth buffer.** `Card_Face` is Unlit Transparent, ZWrite off, queue 3000, so URP sorts per object by distance to the bounds centre; a near tie breaks on registration order, which differs between host and client (same hand, different draw order, every transform correct). To tell "laid out wrong" from "drawn in the wrong order", rebuild the group's frame from the transforms (the rotation axis between two fanned cards is the depth axis) and measure spacing along it; the two need opposite fixes.
- **An arrangement asks the card how big it is; it never stores its own copy.** A hand-typed radius or spacing silently keeps the old shape when the deck is resized. `PokerCardVisual.Size` reads the face quad, `PokerCardGroupVisual.CardSize` asks a held card, the fan keeps only `_pivotDrop` (a fraction of card height) and the row steps by `CardSize.x + _gap`. The face scale is authored against the art's aspect (`Card_Poker/Face` = sprite size in units), so art of a new shape means re-authoring that scale and the root `BoxCollider`.
- **When hand-authoring Shader Graph JSON, the slot type is part of the node.** `MultiplyNode` takes `DynamicValueMaterialSlot` and `AddNode` takes `DynamicVectorMaterialSlot`. The wrong type leaves the input on the node's default with no error, and a value slot promoted to a vector reads the matrix's first row, not its diagonal. Read the generated pass (`ShaderUtil.GetShaderData(...).GetPass(0).SourceCode`) and check every operand. Generate the file from C#, not a shell heredoc, which mangles quotes and `$`.
- **Match Photoshop by blending in gamma, and verify it by reading pixels back.** Photoshop blends stored 8-bit sRGB values while this project renders Linear, so wrap the blend in `LinearToGammaSpace`/`GammaToLinearSpace`. Hardware Darken/Lighten (`min`/`max`) are the only modes that match without conversion, because the sRGB curve is monotonic; Multiply and Screen do not.
- **Screens that answer one moment are panels of one `UIPanelStateGroup`, and the deciding view sits on an object the group never switches off.** Put on a panel, the decider would switch itself off and never hear the next turn (the `UILoadingScreen` trap). A panel with a `UIPopInVisual` pops in on enable and is switched off only in `UIPopInVisual.Hide`'s callback, with raycasts off during the fade. `UIPokerItemWagerBar` (menu ⇄ bet picker)
- **Never add a missing component with `GetComponent() ?? AddComponent()`.** In edit mode a missing component is Unity's fake null, which `??` does not see, so nothing is added (this is why the bet picker never faded in: no `CanvasGroup`). Use `if (!component)` and read the reference back.
- **A picker marks its first entry on open, for mouse and pad alike.** With hover-only marking (`UISelectionGroup._followHoverOnMouse` on), a pad opened over nothing focused has nowhere for the first arrow press to start. Drive cost off `OnSelectionChanged` and the choice off `OnSubmitted`, so both devices share one path. `UIPokerItemWagerBar`
- **A generic usage binding cannot name a key per device.** A single `*/{Submit}` binding displays as "Enter" under every mask. Bind each device explicitly (`UI/Submit` = `<Gamepad>/buttonSouth` + `<Keyboard>/enter`), and put a key the EventSystem runs on onto a face with `UIActionKeyLabel`, not `UIButtonHotkey` (`Button_Choose`).
- **A reference board asks the rules for its content; it never keeps a copy.** Each row calls the hand asset's own `GetName`/`GetDescription`/`GetExampleCards`, so a hand added to `PokerHandDatabase` appears with no other edit. A pop grows from the target's pivot, authored on the prefab, never from an offset computed in code. `UIPokerHandHelper`, `UI_PokerHandRow`
- **Overlapping cards in a layout use negative spacing plus `reverseArrangement`.** The first card is the last sibling, so it lands leftmost and draws on top; a shorter hand switches the rest off. A text column holding a wrapping description needs `childForceExpandWidth` on, or the text wraps at its own preferred width after two words. `UI_PokerHandRow`
- **What the rules forbid is hidden; what the player merely cannot afford is dimmed.** A stage that asks a different question gets its own bar rather than the full bar with most of it switched off, and each bar decides its own visibility from the running stage so exactly one is up.
- **A second currency gets a second readout, never the same one with a different icon.** An icon alone is the only thing telling two pots apart, and nobody reads it at a glance.
- **A notice offers one method per shape it can take, never one method with a `detail` string.** A name and a count are drawn differently, so the caller picks the shape and cannot hand it the wrong-looking content. Clone the target row from the name label it has to match. `UIPokerActionNotice` (`Show` / `ShowAmount` / `ShowTarget`)
- **A HUD readout is about the player looking at it; the room is read off the room.** Every rate is already over its owner's head, so a HUD listing all of them is a second copy kept in step by hand. The bar's colour comes from a serialized `(threshold, colour)` ladder, and the HUD meter is hidden while the table waits (`Phase == Waiting`). `UIPokerHallucinationBar`, `PokerHallucinationTagVisual`
- **A countdown reads whichever clock is actually running.** A beat where nobody holds a turn (`PokerCardLookStage`) has only the stage clock, and reading `TurnRemaining` there shows a bar frozen at 00:00. Show on `HasTurn || HasStageTimer`, pick the source on `HasTurn`, and tick on either clock. `UIPokerTurnPanel`
- **A countdown is for a wait somebody is being held through, not for a beat that passes on its own.** A clock says "hurry" and a close button offers to skip what nobody is waiting on. `UIPokerRankingPanel` has neither.
- **A transition that hides a change must contain it, and one number says when.** Logic owns the timing and the view reads it: `PokerHallucinationController.ApplyDelay` (`PokerHallucinationPacing.CloseDuration`) is when rungs land, and `UIPokerHallucinationBlink` is shut on exactly that frame. **The eye stays shut for the pacing's hold after the switch** (`HoldDuration`, then `OpenDuration`): a blink that opens the moment the change lands shows every effect easing in , so `PokerHallucinationPacing.HoldDuration` is never shorter than `EffectEase`, the one ease every effect runs on (handed to each behaviour through `Run`), and the rungs are re-applied at its end so a change landing in the hold is still hidden. `TransitionDuration` is the whole beat (close + hold + open), which is what the consume pacing and the roll lead-in wait on. Whatever the switch sets off must not add a delay of its own (`PokerRoomController` swaps at once), or the change happens in front of an open eye. A change arriving mid-blink folds into the running beat; release the guard before the trailing re-check.
- **DOTween's UI module is not in this project, so fade a `CanvasGroup` by value.** `DOFade` on a group fails to compile with a misleading receiver-type error. Use `DOTween.To(() => group.alpha, a => group.alpha = a, target, duration)`.
- **An announcement lasts exactly as long as its moment.** Read its lifetime from the same number the beat runs on, and budget the fades inside that lifetime, so the card can neither outlive the beat nor fade before it.
- **A control that asks for a state the data already answers is a second answer that can disagree; derive it instead.** Whether a player holds cards is derived from the cards and drives `IsHaveCardOnHand` directly. Subscribe to `OnHoleCardsChanged` as well as `OnStateChanged`, because the list and the status replicate in no fixed order (a deal writes the list, then `Active`). `PokerHandPoseController`
- **A button inside a layout group that controls child size needs a row of its own.** With `childControlWidth`/`Height` and `childForceExpandWidth` on, a bare button collapses to nothing, and once given a preferred size it stretches to full width. Wrap it in an empty rect carrying the `LayoutElement` height, with the button centred inside at its authored size.
- **A key badge built for one letter auto-sizes, with its max at the authored size.** A single letter then renders as before and only "Esc"/"Enter" shrink. `Button_Plate`
- **A button's hotkey must not hold an action anything else runs on.** `UIButtonHotkey.OnDisable` disables its action on the one shared asset, so wiring it to `UI/Cancel` or `Player/Pause` kills that key for the whole game the first time the button hides. Show such keys with `UIActionKeyLabel`, which only reads the binding.
- **Escape is one key with one handler; what is on screen decides what it means.** Two actions on one key both fire, so a board dismissed with Escape would also open the pause menu. Anything dismissible pushes onto `UIEscapeStack` while it is up. `UIPauseMenu` calls `DismissTop()` first and only opens if nothing was dismissed. Dismissal is newest-first, and each handler is popped before it is invoked.
- **Removing a hotkey component or an action leaves its prefab-instance override behind.** An `_action` modification pointing at a deleted asset stays in `m_Modifications` and survives merges. Afterwards, sweep prefabs and scenes for unresolved fileIDs under the actions asset's guid and strip them.
- **Panels that answer the same question share one slot, and each decides its own visibility so exactly one is up.** "What is the table waiting on, and for how long" is bottom centre, a title over a `UITimerBar` (`TurnPanel`). Build a new one by copying the existing rect and layout, and instantiate rows with `PrefabUtility.InstantiatePrefab`. `Object.Instantiate` of a sibling silently drops the prefab link, so the copy stops receiving restyles.
- **A loading screen owns a minimum visible duration, and the bar spends that hold arriving.** One that flashes past reads as a glitch. `Hide` hands the bar the remaining time (`UIProgressBar.SetProgress(value, duration)`) so it does not sit at 100%. The floor lives on the screen, so every caller gets it. `UILoadingScreen._minimumShownDuration`
- **A screen that hides itself hides a child, never its own GameObject.** Components on a disabled root never run `OnEnable`, so whatever drives the screen subscribes to nothing and it can never wake again, with nothing logged. Toggle a serialized `_content` child and keep the root alive. `UILoadingScreen`
- **The cursor is a counted release, never a toggle.** `PlayerController` holds a base lock for its lifetime, and screens that need pointing pair `CursorController.RequestUnlock`/`ReleaseUnlock` in their own hooks so overlapping holders cannot yank the cursor from each other. At the table the default is inverted: `TableCursorController` holds a release for its whole life and gives it back only while the look button is held. `ReadLookInput` early-outs on `!IsLocked`, so a freed cursor stops the view for every holder. `UIPauseMenu`
- **A card is picked by pointing at it, not by a button beside it.** A row of UI buttons would be a second copy of the cards, kept in step by hand. `PokerCardPickController` raycasts through the cursor and takes the nearest hit that is one of our cards, because `RaycastNonAlloc` does not sort and cards overlap on purpose.
- **A card chosen by pointing is marked, then committed as one set.** A click marks, a second click unmarks, and the set commits when as many are marked as the player is still owed (`ViewableHoleCards` minus those already turned). The lift is decided in one place (`ApplyLift`), with chosen outranking hovered. Once the set spends every look still owed, the whole hand stops being pickupable at the commit and `CanPick` asks `Remaining > 0`, so nothing left on the table hovers afterwards. `PokerCardPickController`
- **A hovered card lifts its art, never its collider, and one method writes the art's height.** Moving the collider with the lift pulls the hit box out from under the pointer, and the card flickers between hover and unhover. The root holds the collider and moves only when the card travels. The lift and the flip move `Pivot` beneath it and are summed in `ApplyArtHeight`, because two tweens on one property means whichever ticked last wins. Thickening the collider instead shadows the card behind it. `PokerCardVisual`, `Button_ActionPad`
- **An anchor resolved from the rendered rig is re-checked, never cached once.** `PlayerRigController.RenderedRig` depends on `IsOwner`, which is not settled before spawn. A holder cached on the first call is pinned to the wrong rig on whichever machine asked early (right on host, wrong on client). Keep the holder and re-parent it when the bone changes. `PokerCardFanVisual.ResolveAnchor`
- **A moving card takes its new parent when it lands, never when it is told to move.** Reparenting at the call makes a waiting card ride a moving hand before it takes off. `ArcTween` flies in world space and reads the destination off the parent every frame; `Land` reparents at the end. `PokerCardVisual.PlaceAt`
- **Card layout is a group, and a picked card moves between two groups.** `PokerCardGroupVisual` holds its cards, resolves its anchor and answers slot position and rotation. `PokerCardRowVisual`/`PokerCardFanVisual` are the arrangements, and a new arrangement is a new subclass, not a branch. A group inserts a card at its place in the deal, not at the end. Whether it closes up around a card that left is the arrangement's call (`SlotOf`/`SlotCount`): the fan closes up, the row keeps each card on its dealt spot.
- **Send a batch as one replicated write; never let the view infer a batch from timing.** One RPC per picked card reached the host as N changes and a client as one, so view-side patches guessing the batch were right on one machine and wrong on the other. `LookAtHoleCardsRPC(int slots)` takes the whole set, refuses it whole with the gate named, and writes `LookedAtHoleCards` once. `PokerCardPickController`, `PokerPlayerData`
- **Cards moving together leave their group all at once, then depart one after another, and a card in flight is never snapped.** Each `Remove` re-lays the group, which snaps any movers not yet taken. `PokerHandVisual.LeaveGroup` calls `Remove(card, layout: false)` for every mover and lays each group out once. Each mover is then handed over with `_handOverStagger` (0.15 s) per moved card in a higher slot, rightmost first. `PlaceAt` keeps a waiting or travelling card on its way instead of landing it. The stagger is spent lying on the table; the flight itself is unbroken.
- **A card's flight waits for the hand animation's own cue, never a guessed delay.** Pick-up, put-down and show wait for the `CardPickUp`/`CardPutDown`/`CardShow` markers on the clips, with `_cueTimeout` as a backstop. `PokerHandVisual`
- **A dealt card starts on the deck, departs in seat order, and every place or flip honours its wait.** `PokerDeckVisual` registers itself (hands are on spawned players), and `PokerHandVisual.AddCard` sends animated adds through it. The deck decides whose turn (`PokerDealTurn`, from replicated `InMatch` seats, never from arrival order, which differs per machine). A `PokerDealController` subclass on the deck decides the wait and the flight (`PokerDealArcController`). The wait lives on the card (`_departAt`), so a non-animated re-layout mid-deal cannot snap a card ahead of its turn. A late join places cards directly. `PokerDealPacing` holds the per-card wait and flight; the arc controller reads it and `PokerDealStage` waits `DealDuration(players, cards)` on the same asset, so the stage can never move on with cards in the air.
- **Name an event after what changed, not after the object it changed on.** An event raised by nine values wakes every view on every change. `OnHoleCardPresentationChanged` carries what `IsHoleCardVisible`/`IsHoleCardInHand` are built from, and `OnStateChanged` keeps "anything about this player". Add a new event when a consumer would otherwise have to re-derive why it was called. `PokerPlayerData`, `PokerHandVisual`
- **A player is picked by pointing at them, and what is outlined is exactly what the click commits.** `PokerColorfulPickController` raycasts onto `AimTarget`, the click sends the seat already outlined, and hover eligibility asks the server's own predicate (`PokerColorfulPickStage.CanBeFed`). Your own body is the answer only when nothing else is hit. Picking yourself is your name on your own HUD meter (`UIPokerColorfulSelfPick`). Resolve the stage only when the id or turn changes: `FixedString.ToString()` every frame is a per-frame allocation.
- **A local hover is ORed with the replicated state, never written into it.** A cursor passing over someone is not a table move; replicating it sends a message per twitch, and overwriting would let hover and replicated outline switch each other off. `PlayerVisual.SetLocalOutlined`
- **A card's hover rim is a sibling mesh, not an inverted-hull outline.** A box 0.002 thick has no sideways faces to grow, so a hull draws nothing. `Card_Poker/Pivot/HoverOutline` is a slightly larger box wearing `Card_HoverOutline.mat` (the `CardSilhouette` alpha, so corners round) at queue 2999, one before the faces, and it lifts and flips with `Pivot`. `PokerCardVisual.SetHighlighted`
- **A renderer on a prop that is not part of its look carries `PropPaintIgnore`.** Otherwise a hallucination that paints every renderer under the prop paints it too; the card wave would draw the card picture onto its own outline. `PokerHallucinationMaterialBehaviour.Paint`
- **Shots about the player's own place need a place in the match; shots about the table do not.** A mid-match arrival has no cards or stake, and an own-seat shot would park their view on empty table. Gate on `InMatch` (not `IsInHand`, which a wager placed before the deal would read as nobody). `PokerStageCameraBinder._requiresPlaceInMatch`
- **Where a card is (table or hand) is derived, not replicated.** `IsHoleCardInHand(slot)` = `!IsFolded && !HandRevealed && HasLookedAt(slot)`. `LookedAtHoleCards` is Everyone-read, because lifting a card is a public act, while `IsHoleCardVisible` (which asks `IsOwner`) keeps the face private. Get that backwards and only the owner sees the pickup. `PokerPlayerData`
- **The pointer's look is a ranked set of requests on `CursorVisualController`, and each look is its own child object.** `Request(state)` returns a handle, and the highest `CursorVisualState` wins (`Default` 0, `Interact` 10, `Skull` 20), so a beat's look survives the pointer crossing a button. While any look is up, the hardware or virtual arrow is hidden through `CursorController.RequestArrowHidden`. `Interact` is requested generically from the static `UIButton.OnPointerOverChanged`, so no button prefab carries cursor wiring. World objects request it themselves (`PokerCardPickController`). A new look is a child plus an enum value, never a branch.
- **The cursor is the one thing on its own canvas.** On the camera canvas, 3D models on the UI sort by depth and can draw over the pointer, and no sort order fixes that. `UI_Cursor.prefab` (in `Bootstrap`) is Screen Space - Overlay at sorting order 32767 with its own scaler and no raycaster. `CursorVisualController.Follow` passes a null camera. The one exception to the single-canvas/scaler rules.

- **The pad's pointer is the Input System's `VirtualMouseInput`, never a hand-written cursor.** It creates a real `Mouse`, so everything reading `Pointer.current` works from a stick unchanged; the wrapper only decides *when* it runs (never on keyboard). `UIVirtualCursor`
- **Seated play is a second look action, not a rebind.** At the table the left stick looks because the right stick drives the cursor; rebinding the standing action would break walking. `Table/Look`, read by `PlayerController` while `_bodyAnchored`.
- **The cursor lock belongs to the mouse alone.** `InputSystemUIInputModule` drops every `MouseOrPen` pointer while the cursor is `Locked`, and the pad's cursor is a `Mouse`, so locking kills hover and clicks. `TableCursorController` holds an unlock released only while the look button is down; on gamepad `PlayerController.ReadLookInput` skips the `IsLocked` gate.
- **A device the game invented is not a device the player is holding.** Generic bindings match the virtual mouse, which silently flipped the scheme and turned the view. Refuse `InputDevice.native == false` and check `action.activeControl.device` against the scheme. `InputSchemeController.SchemeFor`, `PlayerController.ReadLookInput`
- **A `PassThrough` action performs on release as well as press, so the callback reads the value.** One click otherwise acts twice, and the frame helpers do not fix it: `if (!context.ReadValueAsButton()) return;`. `PokerCardPickController` on `UI/Click`
- **An action that drives the virtual cursor must not be bindable by the virtual cursor.** An action bound to `<Mouse>/leftButton` latches and nothing can ever be clicked. Build a private `InputAction` on the pad's south button — the rare action that must *not* be an `InputActionReference`. `UIVirtualCursor`
- **One act is one action; repoint consumers before deleting a duplicate.** After deleting from `.inputactions`, prove no `action.id` moved and every serialized `InputActionReference` still resolves. `PokerCardPickController` uses `UI/Click`.
- **A pad gets a cursor only where there is something in the world to point at.** `CursorController.IsPointerWanted` is a counted request held by `TableCursorController`; menus ask for none and uGUI focus runs them.
- **Anything on the player about *this* machine is owner-gated, and ownership is unknown in `OnEnable`.** Every copy of every player runs it, and balanced counters hide the bug. Bind from `OnNetworkSpawn` behind `IsOwner`, re-bind in `OnEnable` behind `IsSpawned && IsOwner`, idempotent behind one flag. A cue-driven reaction only its victim should feel is the same case, since a cue fires on every client drawing that rig. `TableCursorController`, `PlayerCameraShake`
- **A screen covering a wait blocks input by disabling named action maps, never devices.** Devices take menus and cursor with them; `blocksRaycasts` stops no actions. Re-enable only what you disabled. `UILoadingScreen._blockedActionMaps`
- **Cover a wait from the event that starts it, not the one that answers — leaving as well as joining.** `GameNetworkManager.OnConnectStarted`/`OnGameLeaving`, `UINetworkLoadingBinder`
- **Every start must end in an outcome the UI hears.** A screen raised by one event and cleared by another is stuck on any path that skips the second. Report failed guards through the failure event and raise the start event past the guards. `GameNetworkManager.StartHost`
- **Waits while the game may be paused use unscaled time.** Loop on `Time.unscaledTime` with `Awaitable.NextFrameAsync`; tweens `SetUpdate(true)`. `UILoadingScreen`, `UIProgressBar`
- **A list rebuilds by re-binding its views, never destroy-and-reinstantiate** — `Destroy` is deferred, so the old set draws for a frame.
- **A key shown on a face is read from its binding, never typed.** Size for a word ("Enter") and auto-size. `UIActionKeyLabel`
- **Draw selection in a list as a change of tone, not size** — a swelling row shifts its neighbours.
- **A view fed by two network objects subscribes to both; arrival order is not decided.** Right on host, wrong on client is the tell. `UIPokerRankingRow`
- **A view finds the running stage through the replicated stage id, never `CurrentStage`**, which is server-only. `GameMode.FindStage(Data.StageId.Value.ToString())`, `UIPokerItemWagerBar`
- **A board reporting a finished moment keeps its own snapshot**, refreshed only from data that still has content. A winner everyone else folded to is still turned over and evaluated, so their row shows both the cards and the hand type; folded players are never on the board. `UIPokerRankingRow`
- **A view counting across players subscribes to every player, not only the roster** ("re-sitting fixes it" is the tell). `UIPokerStartPanel`
- **A view draws its state when bound, not only on change** — a change-guard skips a fresh slot wearing the prefab's look.
- UI reads the mode's `*Data` and the stage's own methods; it never computes a rule of its own and never talks to Netcode directly beyond the mode's public API.

## Inspector (Odin)

**A serialized value that must match something else is picked, never typed.** A hand-typed stage id, scene name or action id is a silent runtime failure; a dropdown cannot be misspelled.

- `[ValueDropdown]` wherever the valid values are knowable; where they live in an asset catalogue, bake them into a `*Database` asset and pick from that, so the list works in a build and diffs in version control (`PlayerActionAnimationDatabase`, `GameModeDatabase`).
- `[Required]` on any reference whose absence breaks the object at runtime; `[InfoBox]` with a condition to explain a broken setup in place (`GameModeDatabase` flags a scene missing from Build Settings).
- **Where a value may legitimately name something not authored yet, the dropdown offers but does not confine** — `[ValueDropdown(..., AppendNextDrawer = true)]` (`PlayerActionAnimationDatabase.StateName`; `PlayerActionAnimator` skips a missing state on purpose).
- `[MinValue]`/`[PropertyRange]` on numbers with a real valid range.
- **When the order of a serialized list carries meaning, say so on the field** — `PokerStageSequence._stages` runs in list order.
- Reference the objects themselves, never string ids kept in sync by hand.
- **A shader's `[Enum(...)]` fails silently past seven pairs** (draws a bare float). Write a `MaterialPropertyDrawer` (`UIBlendModeDrawer`, `[UIBlendMode]`); the enum order is the shader's branch order — say so in both files.
- **A member an attribute names with `nameof` must exist in a player build.** Wrapping a `[ValueDropdown(nameof(X))]` source in `#if UNITY_EDITOR` compiles in the editor and fails only the build (CS0103). Keep the method unconditional and put `#if UNITY_EDITOR` inside its body, returning an empty list otherwise. `PokerHallucinationBlendShapeEffect.ShapeNames`
- Odin is inspector UX only: never let an attribute change runtime behaviour.

## Gameplay architecture

New features follow these.

- **A hallucination is a ladder of `(threshold, pool, drawCount)` rows: a rung draws from its pool, effects stack, and re-climbing re-draws.** A draw never repeats within a climb; the controller is owner-only. `PokerHallucinationTiers`, `PokerHallucinationController`
- **Effects that must never run together share a group; never rely on the draw missing.** A group entry rolls and runs one member; live rungs are one group per category. A group only excludes within one draw, so a conflicting pair lives in one rung's pool only. `PokerHallucinationGroupEffect`, `Hallucination_HeadSize`
- **An effect in no rung never runs, and nothing says so.** Authoring an effect and adding it to a ladder are two steps. `Player_Poker` runs `PokerHallucinationTiers` (`_Sample` is scratch); verify pools through `SerializedObject`. `Hallucination_MushroomPeople`
- **A `ScriptableObject` is config; what runs is a scene object.** Live state on a shared asset lets one rung silently tear down another's effect. The asset holds config and `Attach`; a `PokerHallucinationEffectBehaviour` child per rung holds mutable state (`Stop`, `OnDestroy` backstop, `LingerSeconds`). Declare Unity messages once in the base with a hook (`OnDisposed`). `PokerHallucinationEffect`
- **What an effect acts on is a separate asset from what it does.** "Scale the head" and "scale the body" are one effect with two targets. `PokerHallucinationTarget`
- **A prop is asked to wear one of its own looks, never handed a model.** The effect names the variant; the prop owns its meaning (counted requests, last caller wins, `OnVariantChanged`). A look swaps `sharedMesh` on the shared skeleton, never hides bones (hiding `Root_M` takes the camera). Name variants for what the prop becomes. `PropVariantController`, `PokerHallucinationVariantEffect`
- **Something attached to a bone is placed in the pose it will be seen in, not the bind pose.** The rig sits for the whole game, and a pose authored against the T-pose lands somewhere else once the clip lifts the shoulder (the extra arm came out 12 cm high, hidden behind the head). Play `Sit` in Play mode, set the world pose there, read the local pose back off the bone and write that into the prefab, and judge it from a render. `ExtraArm` is `Hand_Attach` (art prefab with its own `EZSoftBone` chain) under the body rig's `Scapula_R`, rising behind the right shoulder and reaching forward over it.
- **A look can be an animation.** `PropVariantAnimator` sets `IsTransformed` while the prop wears `Transformed` and reads it on enable, so a cap spawned mid-hallucination arrives transformed. `Animator_Mushroom.controller` plus one override controller per kind; `AlwaysAnimate`, since the picker's copy is drawn only by `UICamera`. When the transform take ends the cap breaks into one of four looping dances (`Dance1`–`Dance4`, shared by every kind), picked by the `DanceIndex` int `PropAnimatorRandomIndex` rolls on enable — local, since how a cap looks is per screen already.
- **An asset cannot reference a scene object, so the scene registers what assets may ask for, keyed by an enum.** `PokerScenery` (`PokerSceneryGroup`), `PokerHallucinationSceneryTarget`
- **A room is authored in the scene and switched on, never spawned from a prefab.** The controller holds `(PokerRoomVariant, objects)`, registers itself, counts requests and swaps at once — the blink hides the change. It switches every other room off before the chosen one on, so a piece listed in two rooms stays on, and warns on enable about a room entry whose object is missing: a lost reference is a room that silently never switches off (the `Default` room once did exactly that). `PokerRoomController`, `PokerHallucinationRoomEffect`
- **A distortion must Replace its subject's material; only a tint can be an Add pass.** A pass on top cannot bend what is beneath; Replace still gets the picture, because the rect is in the mesh and the atlas is global — `Card_Wave` clamps its bent UV to the card before remapping into the rect, so it never samples a neighbour in the atlas. `Card_Wave` (Replace), `Card_Rainbow` (Add)
- **Order transparent passes with the render queue, never the material array.** Same-queue passes tie unpredictably (rainbow 3001, faces 3000). On URP set `_QueueOffset` — `renderQueue` alone is silently reverted — and read it back. `Card_Rainbow.mat`
- **An added pass on a card samples its own texture at `uv0`; the atlas rect lives in UV2 and only the card graphs read it.** `Card_Pattern.mat` (`Sprites/Default`, `_MainTex`)
- **Add and Replace are different operations.** Add appends one pass; routing it through a single-winner override silently makes it a replacement. `PropPaintMode`, `PlayerMaterialOverrideController`
- **A renderer's authored materials are captured once, by one owner, never by each painter.** Otherwise a second painter captures the first's paint as original and it can stick forever. `PropMaterialOverrideController.Claim(renderer)` is the single writer; callers null-check it (cards die between hands).
- **An event relayed through a generic seam must have the seam's signature.** A lambda-wrapped handler cannot be unsubscribed. `PokerScenery.OnInstanceChanged`
- **Split a module by rename plus a new small file, never by surgical delete.** `AssetDatabase.MoveAsset` carries the guid, so the prefab's component keeps its serialized settings as the renamed class and the other half is written fresh beside it. ## Asset naming conventions

- Prefabs: `UI_` for UI (`UI_Screen_<Name>` full-screen, `UI_<Name>` components), `Button_` for buttons, no prefix for gameplay. Clips `Animation_<StateName>.anim`, controllers `Animator_<Context>.controller`/`.overrideController`, colocated with their prefab. Scenes short PascalCase (`Bootstrap.unity`, `Gameplay_Poker.unity`). ScriptableObject assets named after their class.
- **A font family is a folder of faces plus their TMP assets, which are Dynamic.** Dynamic rasterises unbaked glyphs (Steam-name accents) instead of boxes; wire the bold face into the weight table. Created by script, `AddObjectToAsset` the atlas and material or it loads broken. Display fonts fall back to `LiberationSans SDF - Fallback` (Dynamic), not the Static `LiberationSans SDF`. `Fonts/Skranji/`
- **World pieces that carry behaviour are prefabs (model, components, anchors), never hand-assembled scene objects.** One edit reaches every instance. `Seat_PokerChair.prefab`, `PokerTableVisual.prefab`
- **A spawn point sits where the prefab's root belongs.** Player roots are at the feet, so a seat's point is on the floor and the sit animation supplies height.
- **Teleport through `NetworkTransform.Teleport`, never the transform alone.** A bare write reaches others as a delta and they glide the whole way. Authority only (`OwnerNetworkTransform`); disable the `CharacterController` around it. `PlayerController.Teleport`
- **Environment props take colliders from the FBX importer (`addColliders`).** Enabling it over a hand-fitted scene silently doubles colliders or adds none where the auto collider was removed as an override — revert those, delete added-override `BoxCollider`s (`PrefabUtility.IsAddedComponentOverride`). Hand-fitted boxes use `MeshFilter.sharedMesh.bounds`, never `Renderer.bounds` (Z-up FBXs at `rot x=270` lie on their side); verify `Collider.bounds` ≈ `Renderer.bounds`.
- **Measure a seated fit with the Animator running, never `SampleAnimation`.** Sampling leaves the avatar root at bind pose (17 cm off on the sit clips), so furniture fitted from it floats the character.
- **Seat facing is derived from position (`Atan2(-x, -z)`), never typed; layout code that rewrites it must be able to stand down.** `PokerSeatRingVisual` rewrites chairs on `OnEnable`; `_placeSeats` off keeps hand placement. `_radius` 0 is measured off the chairs (currently `1.1634302`) — keep that when re-authoring or every seat shifts.
- **A model turned wrong is fixed in its own prefab, not by an offset in the code that aims it.** The seat root must keep meaning "square to the table". `Seat_PokerChair`
- **An Animator whose renderers are all disabled freezes under `CullUpdateTransforms`, and the stale pose looks real.** Use `AlwaysAnimate` on hidden rigs that are measured, drive props or feed bone lookups. `PlayerVisual`
- **Fix "switched off" in the owning prefab, never with a scene override** — overrides die in merges; `PrefabUtility.RevertPropertyOverride` after. Before discarding a re-serialized scene, map each guid to its `.meta` (`grep -rl <guid> Assets --include=*.meta`): it may be a real override.
- **A scene override beats the prefab; check the scene before believing a prefab edit landed.**
- **An editor write is done only when the file on disk says so; save APIs report success without writing.** `LoadAssetAtPath` reads memory — verify with `git diff`/`grep`, and stop on a `false`/`null` save. Recipes that write:
  - ScriptableObject: `AssetDatabase.SaveAssetIfDirty(asset)`, not `SetDirty` + `SaveAssets()`.
  - Prefab: `PrefabUtility.SavePrefabAsset(go, out bool ok)` on the in-place asset; if that fails, edit the YAML, `ImportAsset(path, ForceUpdate)`, read back via `SerializedObject`.
  - `ProjectSettings/*.asset`: `SaveAssets()` **and** `ExecuteMenuItem("File/Save Project")`.
  - `TextureImporter`: via `new SerializedObject(importer)`, `WriteImportSettingsIfDirty`, `ImportAsset(ForceUpdate)`, then read the `.meta`.
- **PNGs under `Assets/Textures/**` import as Sprites via `Assets/Settings/Presets/UISprite.preset`; never widen its glob.** `Assets/Art/**/Texture` 3D maps need mipmaps/Repeat. Build presets from a seed PNG, not an existing sprite (its 9-slice would become default).
- **Move assets with `AssetDatabase.MoveAsset`, never on disk** (keeps guid); then check for null materials and missing scripts.
- **Renaming a serialized field drops its value even though the script guid survives.** Use `[FormerlySerializedAs]` or rewrite the old key in every `.prefab`/`.unity`/`.asset`; verify non-null via `SerializedObject`.
- **Rename a mechanism when the game outgrows its first use; domain comments keep domain words.** `PokerMushroom*` → `PokerItem*`. Entries differ by prefab (`PokerItemDatabase.Entry.WorldPrefab`), never a tint.

## Editor settings that affect how you write code

- **Domain Reload is off: reset every static in `[RuntimeInitializeOnLoadMethod(SubsystemRegistration)]`** — a `static event` to `null`, or it holds handlers from past sessions (`static readonly` exempt). `SteamController`, `UIManager`. Never subscribe to another static's event there (order undefined); subscribe in `AfterSceneLoad`. `CursorController`
- **Auto Refresh is off: plain `AssetDatabase.Refresh()` after writing scripts; never `Refresh(ForceUpdate)`.** A force reimport re-serializes untouched assets and re-binds `InputActionProperty` fields to the wrong action (clicks landing nowhere). Reread one asset with `ImportAsset(path)`.
- **A `RunCommand` cannot import a new asset, yet reports success.** Tell: guid resolves, `FindAssets` finds nothing, CS0246. Hand the import to the person at the editor. Never `AllowAutoRefresh()` (breaks the refresh counter). A hand-written `.cs.meta` (`fileFormatVersion: 2` + unique `guid`) is adopted and unblocks wiring.
- **Create folders with `AssetDatabase.CreateFolder` in their own command**, never `Directory.CreateDirectory` — writes into an unregistered folder fail silently. Check `IsValidFolder`; reload after `CreateAsset`.
- **Delete with `AssetDatabase.DeleteAssets(paths, failed)`, never the shell or `DeleteAsset`** (a command containing `DeleteAsset` is rejected whole). Check `GetDependencies(buildScenes, true)` first. A script deleted from the shell can freeze compilation (CS2001, then all `Game.*` unresolved) until a person focuses the editor; diagnose with `AssetPathToGUID(..., OnlyExistingAssets)` and `CompilationPipeline.GetAssemblies()` `sourceFiles`. MPPM clones need `Library/VP/mppm*/Library/Bee` and their `.csproj` deleted, then `RequestScriptCompilation(CleanBuildCache)`.
- **Confirm the connection is on the main editor before trusting writes.** An MPPM virtual player is read-only and every save no-ops; `Application.dataPath` under `/Library/VP/` means a clone. `McpVirtualPlayerGuard` stops the bridge in clones.
- **UI text is TextMeshPro** (`TextMeshProUGUI`, `TMP_Text`…), never `UnityEngine.UI.Text`. **Input is serialized `InputActionReference`**, never `actions["Look"]`.
- **Mouse delta is never scaled by `deltaTime`; a stick is a rate and is.** A held `Value` action stops raising `performed`, so look is polled and branches on `InputSchemeController.IsGamepad`. `PlayerController.ReadLookInput`
- **The device in hand comes from `InputSystem.onEvent` filtered by `EnumerateChangedControls(device, 0.15f)`, not `onActionChange`** (which misses unbound/disabled actions). `InputSchemeController`
- **Every binding carries its scheme `groups`, or `MaskByGroup` labels come back empty** (composites always do). A label's "unchanged" guard must treat a device change as a change.
- **Edit `.inputactions` via `asset.ToJson()` and prove no `action.id` moved** (reference fileIDs derive from ids). Each action has two `InputActionReference` sub-assets, so a YAML fileID can mean another action — check with `TryGetGUIDAndLocalFileIdentifier`.
- **A scripted scene `NetworkObject` gets `GlobalObjectIdHash = 0` and never spawns** — remove and re-add the component on the saved object.

## Rules

1. Keep the two-assembly split (`Game.Runtime`, `Game.Editor`); don't introduce new asmdefs without a real modularity need.
2. Server-authoritative by default — any gameplay state that must be consistent across clients lives in a `NetworkBehaviour`/`NetworkVariable`, not in a locally-mutated field trusted from the client.
3. No XML doc comments or comment blocks; let naming carry the meaning.
4. Follow SOLID, KISS and DRY; prefer industry-standard patterns over bespoke structure, and keep modules loosely coupled and reusable.
5. Extend through `protected virtual OnX` hooks called from a non-virtual base method — never edit a parent class to accommodate a subclass. Never make a Unity message (`Awake`, `Update`, `OnDestroy`) `virtual`: a subclass forgetting `base.Awake()` is a recurring, silent bug.
6. Every system binds and unbinds through explicit paired lifecycle hooks; never poll for a dependency in `Update()`.
7. Animate with DOTween tweens, not hand-rolled `Lerp`/`Slerp` stepped in `Update()`.
8. Never resolve a dependency by searching the scene (`FindFirstObjectByType`, `FindAnyObjectByType`, `Camera.main`) — serialize it, be handed it, or register it.
9. Name a mechanism domain-agnostically and domain code explicitly; the name must state its purpose on sight. Don't abstract until a second real use exists.
10. A serialized value that must match something else is picked from a dropdown, never typed.

## Maintaining this file

**Write the rule down in the same change that establishes it.** A convention agreed only in chat is gone by the next session — these rules are where the project remembers.

A rule earns its place when either is true: **it repeats** (the same correction or the same shape has come up twice — don't wait for a third), or **it matters** (getting it wrong causes a silent failure, a leak, or a bug that is hard to trace back, even if it happened once). A one-off decision with no consequence stays in the code.

When adding one: put it in the section it belongs to instead of appending a new one, cite the file in this repo that demonstrates it, and fix any existing rule it contradicts. A rule that disagrees with the code is worse than no rule, because it will be trusted.

**Keep each rule short**: the rule in bold, one to three sentences on the failure it prevents and how to apply it, and the file that shows it. No debugging story, no measurement log — this file is loaded into every session, and its length is paid for every time. When a feature is deleted, delete or generalise the rules that only described it in the same change.
